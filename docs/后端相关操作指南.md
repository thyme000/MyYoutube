# 登录校验

前端需要保存用户信息,后续请求中需要在请求头中携带用户信息

```
前端请求
  │
  │  Header: Authorization: Bearer <token>
  ▼
Spring 拦截器 (LoginInterceptor)
  │
  ├─ 解析 token → 拿到用户ID/信息
  ├─ 存入 UserContext (ThreadLocal)
  │
  ▼
Controller → Service → Mapper
  │
  │  任意层都可以调用 UserContext.getUser()
  ▼
请求结束时，拦截器 afterCompletion 清除 ThreadLocal（防止内存泄漏）


```

```
登录时：
  用户输入账号密码 → 后端验证通过
    → 生成一个随机 token（如 UUID）
    → 以 "LOGIN:token值" 为 key，把 UserDTO 存入 Redis
    → 把 token 返回给前端

之后每次请求：
  前端把 token 放在 Header 里发给后端
    → 拦截器拿到 token
    → 去 Redis 查这个 token 对应的 UserDTO
    → 查到了 → 说明是真实登录用户 → 存入 ThreadLocal
    → 查不到 → token 无效/过期 → 拦截返回 401
```

# 返回前端的结果集用法

```
// 1. 成功，没有数据返回（如：删除操作）
return Result.success();
// → { "code": 200, "message": "操作成功", "data": null }

// 2. 成功，返回单个对象（如：查用户信息）
return Result.success(userDTO);
// → { "code": 200, "message": "操作成功", "data": { "id":1, ... } }

// 3. 成功，返回列表（如：视频列表）
return Result.success(videoList);
// → { "code": 200, "message": "操作成功", "data": [...] }

// 4. 成功，返回分页数据
return Result.success(PageResult.of(page));
// → { "code": 200, "message": "操作成功", "data": { "total":100, "list":[...] } }

// 5. 失败，自定义消息（如：用户不存在）
return Result.fail("用户名或密码错误");
// → { "code": 400, "message": "用户名或密码错误", "data": null }

// 6. 失败，用枚举（如：未登录）
return Result.fail(ResultCode.UNAUTHORIZED);
// → { "code": 401, "message": "未登录或登录已过期", "data": null }
```
